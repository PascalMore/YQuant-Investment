# 候选契约抽查清单（恢复前判定“只剩收尾”）

用于把剩余工作归类为「仅补报告/收尾」之前。发现实质缺口即记录为候选未完成，不按行政收尾放行。
每项都必须落到「文件:行号 / 实际命令输出 / 实物字段」，不接受自述。

## 1. 公开入口是否真的执行

沿 CLI / facade 追踪实际业务调用，逐层分清结果：

- 固定返回 partial、verify 误入 plan、只实现检查点 helper 却未调用真实管道 = 未完成实现，不是只缺交接。
- 流式契约看实际载体：全窗累积 list ≠ 有界迭代；初始化 labels 但从未产生 LabelRow ≠ 标签分离已交付。
- 用正向产出 + 两批以上消费用例证伪这些缺口，不能用“现有 suite 全绿”替代。
- 同时核对入口 `main` 的最终返回、子进程 `returncode`、summary 与报告 verdict；命令账本只记录子进程退出码，不能证明外层研究按证据不足退出。
- 缺失真实样本时不能走正常完成分支。
- 对状态型执行链，从原始响应经 adapter 追踪到公共 consumer 的实际提交：在 await 前登记的共享 handle 必须与发送侧更新的是同一对象；返回事实必须进入累计数量、现金、费用、预留与 generation 的原子更新，不能只更新水位却提交默认零 delta。同步、撤单后迟到结果及启动恢复也应沿同一事实链核对；纯解析/并发 helper 测试通过不能证明这些调用已接通。
- 把验收矩阵拆为“测试存在并执行”“测试经过真实解析/adapter/consumer”“关键断言成立”逐项核对；正常路径永久被健康门禁拒绝，只证明失败关闭，不证明核心能力已交付。
- **对复用同一事实 reader 的历史恢复与实时执行，先核副作用归属，再测失败后的恢复。** 历史查询显式传入局部不可变 binding，不临时覆盖实时 handle 注册表；读失败槽、预算预留与超额风险更新留在各自 consumer 边界，否则历史查询会污染实时账户门禁或并发绑定。用原始响应→adapter→公共 consumer 连续跑“合法→读失败→同一输入健康重读”，断言合法恢复可继续、旧风险未被确认覆盖、没有额外签单或提交；仅有独立的成功与失败用例会漏掉永久自锁。
- **运行账实核对同时覆盖现金和净库存。** 在真实 adapter 已记入非零成交后，让合成 REST 与链读一致地偏离本地账，断言 consumer 仍能检出账实差异、阻断新增且不改已记金额/费用/水位；恢复原观测后只验证契约允许恢复的错误槽，不用清空全部门禁冒充恢复。这样能区分“两个外部读数相符”与“外部读数和本地账相符”。

## 2. 不可逆标准化之前的保护

对分页、去重、合并类 helper，追踪原页校验器的 seen/count 是否确实参与每次调用。
只在最终合并结果检查冲突 = 无法发现已被后页覆盖的冲突。
恢复清单要给出同页/跨页冲突与精确时间对齐的反例；常规样本跑通不能当作防护成立。

## 3. 计划行集与证据级别

- 对照声明窗口检查缺数据的计划行是否保留。
- 不可验证指标保持 `N/A + reason`；无执行证据时写“成交数零”等于把未知伪装成实测。
- 区分 split 跨界、末尾标签缺失、预热不足、裁剪前后计数；不能只核对总样本数碰巧正确。

## 4. 证据保全与验证作者

- 沿写入调用点检查参数冻结是否先于取数、目标冲突是否在副作用前拒绝、日志是否对成功与失败都保留。
- 开发者创建的 `verify-*` 目录仍是开发者自测，不因目录名变成独立验证。
- 历史日志未捕获就如实标缺失，不能事后生成貌似原始执行记录。

## 5. 最终实物规模与授权

- 实测最终源码及测试行数，不沿用 worker 中途估计。
- 需要新文件拆分或触及现行架构例外时，先按既有规则冻结精确职责/路径，再续做。
- 不通过增加预算、或把未验证代码标为只读来逃避拆分。

## 6. 分页检查点失链与部分写入恢复

1. **先对齐三种状态再重跑**：读取 stream 的 cursor/冻结上下界/manifest 引用、相关日分片引用以及已归档 manifest。恢复报“缺少扫描状态”不等于原始页丢失；日终覆盖引用可能使 stream 指向新页链、日记录却只剩旧引用。优先已知主题目录内有界查找，不以全盘扫描或重新下载历史窗口代替定位。
2. **离线复现计划日与扫描窗错位**：在假库保留旧活动窗口，让下一次计划选择另一日，模拟预算截断、闭合和重启。断言实际处理日期、cursor/bounds/ref一致、闭合原窗能正确复核及进入下一合法窗；只验证“不再抛错”会遗漏永久卡旧窗或把窗外日误标完整的问题。旧 day-only 格式、坏hash/错窗/缺引用、墙钟耗尽和连续完整水位都需反例。
3. **把闭合扫描与后续计划分开**：扫描检查点直接绑定其可信 manifest 和原窗口；日终状态不得抹去唯一恢复引用。闭合后的原窗口复核占当前日预算，不能隐式附带无界新扫描；真正 gap/conflict 仍阻断连续完整水位。
4. **写入超时先对账**：工具超时且原生退出/summary缺失时，结果记 UNKNOWN；通过已有自然键、stored/recomputed/官方原文转换后的业务hash核实实际已写子集，再决定幂等续跑。部分行一致不等于整日完整，不追认原ack或exit，也不清库重来。
5. **只恢复授权的最小引用**：确认候选manifest内容hash、kind、cursor和冻结上下界与真实stream精确相符，取得具体namespace/记录/字段的恢复授权。复用应用既有写锁，保存完整旧文档，使用包含旧值条件的 `update_one(..., {"$set": {"scan_manifest_ref": verified_ref}}, upsert=False)` 执行一次CAS；只补引用，不清cursor、不重置retry、不改day complete或水位。匹配数不是1、ack不明或读回异常即停止，不自动重试。
6. **核完整文档而非只核新字段**：读回同一精确目标，断言新文档等于旧文档加获准字段，保存receipt和前后证据。一次单字段生产恢复不授权批量纠正已有标签；后续仍走已审管道。
7. **长摄入用受跟踪的原入口**：首次设计执行方式时，为预计超过前台工具等待上限的已授权CLI使用 `terminal(background=True, notify=True)`，保存session_id、原生退出和逐批summary；同一业务进程未结束不启动第二次apply。若前台动作已经安全拒绝，改后台仍须新的相应授权；未知写入结果先按上步对账，不能用后台重跑掩盖。

## 配套结论规则

- 候选仅部分落盘或尚未通过原冻结回归时，不得把“不要推倒重写”改写为“只准改消费者，禁止修上游候选”。先核对完整调用链和当前失败；在原 Design/allowlist 内完成必要增量修正不等于重做实现。
- 续接正文同时列出：已验证行为、仍失败行为、尚缺的原定测试覆盖。测试数变绿不能替代完整验收。
- 每份测试结果绑定候选哈希或明确的改动前后边界；worker 再编辑后，旧的全绿只作历史基线。
- 对每项静态缺口标明尚待动态证实，禁止把自报剩余项当成已通过事实。
- 修正解释器或文档身份后，从 live task body 及镜像中**删除**相反的现行旧路径/旧哈希，不只追加覆盖说明；历史限制留在旧 run/交接里。
