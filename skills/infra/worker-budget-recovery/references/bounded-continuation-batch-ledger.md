# 有界续批账目与恢复判定

适用于主控接管后的多批串行采集、回填和验证。复用已授权入口及其预算，不重建调度平台；下述步骤不扩大原生产授权。

## 每批执行顺序

1. **接收完成事件，固定批次身份。** 保存原生退出码、原命令、报告目录和 summary 指纹；对工具等待超时与业务进程退出分别记账。
2. **解析实际结果。** 逐条归纳实际处理日期、状态、`inserted`、`updated` 和错误，而非仅看 `planned_dates`。冻结旧扫描可能先完成旧窗；`pending` 也可能有部分入库。
3. **核对真实状态。** 在目标窗口内取得累计行数、按状态分组、完整日与部分日、连续完整水位；将旧错误的尝试时间与本批时间对齐，避免把旧标记算作本批新增失败。游标续传核 manifest SHA、cursor、bounds 和原页哈希，不清状态猜恢复。
4. **裁定可继续的范围。** 按下表区分正常截断、隔离分片失败和来源级失败；保留原失败分片与退避，不能靠新报告目录重置上限。
5. **排除重复执行后续批。** 确认原 apply 已退出、无其他同目标写入进程且下一报告目录未存在，再用原显式入口启动下一有界批，并把真实执行者、session/PID 与通知归属记入原卡。
6. **保存增量账目并读回卡片。** 每批只追加本批差异、证据指针和下一执行身份；不要重发旧 block 产生自激通知。原有独立下游仍按其真实验收条件释放。

## 每批固定记录字段

- **原生退出码**：只认业务进程自身的结果，不认管道末端或启动回执；无法取得则记 UNKNOWN，不靠 summary 补造。
- **summary 指纹**：对实际落盘文件计算 SHA256，使报告与批次输出一一对应。
- **实际日期与增量**：逐来源、逐日记录成功、失败、部分写入与实际自然键范围。
- **累计快照**：冻结窗口内总行数、完整日/部分日、覆盖率、连续完整水位与快照时间；行数覆盖率不冒充完整日比例。
- **逐来源剩余量**：从固定目标日期集合减去该来源实际完整日期集合，分别列未尝试、部分摄入、失败退避与待结算等原因；不要把这些可能重叠的分类直接相加。某来源无到期计划时，仍保留其未完整日期，不能将空计划记成覆盖已齐。
- **失败与退避**：保存 `last_attempt_at`、`next_retry_at`、错误码及所属批次，跨批次保留。
- **下一批身份**：真实执行者、session_id、PID、原入口命令、独立报告目录、原预算和停止条件。

## 停止与续批判定

| 证据 | 动作 |
|---|---|
| 实际结果均完整、整体目标未齐 | 确认无残留写入后正常续下一有界批，不把整体验收提前写为通过。 |
| 分页或预算正常截断，检查点可信 | 从冻结窗口和游标继续；已保存页数不等于目标完整日数，部分写入仍计入真实增量。 |
| 隔离日期网络失败，其余成功 | 保留失败和退避；只读既有 planner，只有下一计划不重试尚在退避或已耗尽上限的分片、也无来源级停止条件时，才继续其它获准日期。 |
| 来源 `results` 为空，stderr 明确网络失败 | 记来源失败，不解释为零数据成功或普通分页截断；先判定该来源的恢复条件，保留另一来源成功实物，不盲目重跑整批。 |
| 未知 ACK、读回冲突、安全拒绝、认证失败 | 停止相应动作或来源，保存事实；不换执行器、凭据、出口或扩大重试。 |
| 覆盖、幂等、增量运行等条件分别达标 | 按原契约登记各项证据，交既有独立门禁；不以其中一项替代其余项，也不自行增加新阶段。 |

读取当前 CLI 的退出码契约后再归类。尤其不要把所有“部分完成”码统一解释为“本批日期齐”：它也可能表示分页未闭合或预算截断。反过来，批次有失败也不抹掉另一来源已经提交的成功数据。

## 只读快照与完整核验

- 进度查询用有界只读聚合，显式约束来源、标的、频率和目标时间范围；只打印业务状态，不输出连接串、凭据或原始异常上下文。
- 把完整 verify 安排在稳定批次边界，除非已有契约提供并发快照一致性。耗时未知时用原入口后台跟踪、完成通知和原生退出，不把短前台时限当成业务预算。
- 若工具时限截断，记“未取得完整核验”，核原进程是否仍存活后再决定续核；不因为只读就无成本重复全量扫描。

## 网络诊断与重发审批

1. 区分业务网络错误与工具审批结果：探针被阻止且未执行时，没有取得任何网络证据。
2. 用户明确要求重发审批时，仅原样重发仍必要的那条命令一次；保留 URL、参数、方法、请求头和执行形状，不改写为脚本或另一工具。再次未获批就停，不循环提交。
3. 将获批后的证据分层记录：未认证端点的 HTTP 401 证明响应可达，不证明 key 有效；归档 HEAD 的 HTTP 200 证明请求成功，不证明完整正文下载、checksum 或数据库摄入成功。
4. 诊断通过后只恢复原授权范围内、且符合原重试/退避条件的业务入口；以该入口实际获取并校验目标数据的结果确认业务恢复。重发探针的授权不扩大为换 key、改代理、清 due 或放宽预算的授权。

## 对外表述

先给新增实物、再给累计覆盖和剩余工作。写明快照时区，区分完整日、部分日、扫描页数和连续水位；不把行政 triage 误报为业务进程停止。若接手后业务仍在执行，明确说明真实执行者与最终结果待确认；既有独立验收完成前不称整体可用。
