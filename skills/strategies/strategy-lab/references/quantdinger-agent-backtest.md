# QuantDinger Agent 回测实操备忘

## payload 与 symbol 格式
- 本机生成器成功样例的 payload symbol 是裸 `BASE/QUOTE`，例如 `SUI/USDT`，生成结果为 `Crypto:SUI/USDT@swap`。
- 不把包含 `@gate:swap` 的字符串直接传入当前模板：已观察到模板追加 `@swap` 后出现双重 @ 和 `marketData.invalidCryptoIdentifier`。指定交易所前应核对当前官方身份解析与生成入口，不用手工替换隐瞒路由差异。

## 数据窗口限制
- 当前本地 Crypto adapter 的 `_RECENT_CANDLE_LIMITS` 对 gate 配置为 10000。曾观察三个月 5m 请求被本地适配器拒绝，15m 请求成功。
- 这是当前路径的本地策略证据，不推导所有交易所、gate 所有产品或官方历史数据接口都只有此保留期。更换数据源后重新验证，不沿用限制。

## 提交、等待与终态读回
- 曾观察 CLI 在约 180 秒返回 deadlineExceeded，而引擎随后完成任务。不能单凭现象断定服务端固定 deadline；须核对 CLI、服务端和实际 job 的各自预算。
- 超时不等于失败或计算停止。保留原 jobId，以既有 `agent_job` GET `/api/agent/v1/jobs/{jobId}` 读回原任务终态，不为取结果重复提交。
- `--wall-seconds` 含义以当前 CLI 实现为准；不修改预算规则绕过限制，不根据预计耗时宣称任务成功。

## 总敞口字段核算
- 先查明字段单位。holdingSnapshots 的 `grossExposure` 曾返回类似 0.02294 的比例，不能再除一次账户净值，也不能把字段名解释为净敞口。
- 用逐仓 `sum(abs(marketValue)) / equity` 交叉核验多空总名义敞口；分母必须明确是策略保证金实时净值还是名义基准。
- 600 点下采样快照只能证明采样点的结果，不能证明全部 bar、成交时点或 bar 内始终满足杠杆限额。
- 胜率只描述已平仓样本，必须同时报告未平仓浮盈亏、费用与期末净值，不能将胜率 100% 解释为无风险。

## 杠杆与预算：禁止混用
- 当前网格 builder 曾观察 `entry_budget=1.0`、每格名义订单预算由 `starting_cash * CELL_BUDGET_PCTS` 计算；payload 的 `leverage=10` 不能单独证明实际订单放大十倍。
- **把 initialCapital 从 1000 改为 10000 会同时改变引擎账户净值，不等价于保证金 1000、杠杆 10 倍。**历史 evidence-10x 仅为 10000 账户规模对照，不是已验证的 10x 保证金模拟。
- 用户要求保证金 1000 USDT、可配置名义预算 10000 USDT 时，订单预算、保证金账本、估值、费用、风险限额与强平估算须分别核对。名义预算不表示启动即持有全部名义仓位。
- 用户最新确认：主收益率=净损益/初始保证金1000；MDD按真实保证金净值相对历史峰值计算，Sharpe也从该净值收益序列计算。10000名义预算仅用于订单规模；不得用其作主指标分母，或将旧10000账户规模结果直接乘十当成已验证的杠杆指标。

## PUMP 部分成交：根因未定
- 历史本地结果确有大量 partial；这只能证明该次模拟的成交行为，不能证明 Binance PUMP 永续真实容量不足。
- 历史 gate 数据的市场身份、成交量单位、合约乘数与引擎参与率尚未完成同窗交叉核验。此前约 130 USDT/bar、真实容量只有 1–2 倍保证金等结论撤销。
- 2026-10-31 本机恢复代理后，无 Key 的 Binance PUMPUSDT 永续行情已可取；最新已收盘 bar 成交额显著高于先前声称值，但不能用当前 bar 直接证明旧历史 bar 或引擎错误。
- 诊断须使用同一交易所、同一永续合约、同一 UTC bar，对比官方 base/quote volume、本地原始字段、乘数转换及执行模型，不在单位和市场身份未定时解释为流动性问题。

## 报告标准
- 多窗口回测按父模块 `strategies` 的 `references/backtest-comparison-standard.md` 输出。历史结果保留；错误结论标记撤销，不用新口径覆盖原始证据。
- 本地关闭计费必须逐任务记录实际 billing 字段；免费状态不等于行情、模型或业务验收通过。
